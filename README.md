# CT Annotation Platform

A database management system for medical DICOM CT data and their
annotations, built around cases (patient + study) that tie together
imaging (imaging studies/series/instances) and generic clinical data
(documents, reports, with tags and consent records). See
[`ARCHITECTURE.md`](ARCHITECTURE.md) for the full design rationale
(schema, RBAC, Kubernetes topology, ingestion pipeline).

## Layout

```
admin-ui/               Browser-based management UI (React + Tailwind)
services/
  ingestion-service/   DICOM upload (per case), de-identification, async processing
  data-service/        Browse cases/imaging studies/series/instances/clinical data, fetch files
  annotation-service/  Create/list/review annotations
  admin-service/       Studies, memberships, cases, clinical data, de-identification profiles
libs/
  shared-models/       SQLAlchemy models + DB session (schema source of truth)
  shared-auth/         Keycloak JWT validation + study-role checks
infra/
  migrations/          Alembic migrations, autogenerated from shared-models
  k8s/                 Kubernetes manifests for the four backend services
  keycloak/            Reproducible dev realm provisioning script
```

Every service is independently runnable, testable, and documented -- see
each `services/*/README.md` and `admin-ui/README.md`.

## Running locally

```bash
cp .env.example .env   # adjust if needed
docker compose up --build
```

This starts Postgres, Redis, MinIO, a dev-mode Keycloak, all four backend
services, and admin-ui. Ports:

| Service | Port |
|---|---|
| admin-ui | 5173 |
| ingestion-service | 8001 |
| data-service | 8002 |
| annotation-service | 8003 |
| admin-service | 8004 |
| Keycloak | 8080 |
| MinIO console | 9001 |

**First-time setup:**
1. `./infra/keycloak/setup-dev-realm.sh` -- provisions the `ct-platform` realm, client (incl. admin-ui login redirect), and a test admin user (see `infra/keycloak/README.md`). Safe to re-run.
2. Apply DB migrations: `make migrate` (see `infra/migrations/README.md`).
3. Open http://localhost:5173, log in as `platform-admin` / `platform-admin`.

## Running a single service outside Docker

See the `README.md` in each `services/<name>/` directory (and
`admin-ui/README.md`) -- each documents its own dependencies, env vars,
and how to run its test suite in isolation.

## Running tests

```bash
make test              # all backend services
make test-ingestion    # one service
```

`admin-ui` has no automated test suite yet -- `npm run lint` (`tsc
--noEmit`) is its only correctness gate; see `admin-ui/README.md`.

## Status

Backend + admin-ui both exist and have been verified end to end (real
DICOM upload through ingestion -> object storage -> data-service ->
annotation-service, driven through the actual browser UI, not just
curl). Not yet implemented: Kubernetes Ingress/cert wiring for a real
domain, CI, dataset snapshot endpoints, and the annotator DICOM viewer
client (deferred -- see `ARCHITECTURE.md`).
