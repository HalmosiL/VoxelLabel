7. Telepítés

  1. git push a feature/clinical-trial-consort-and-store ágra.
  2. A szerveren git pull, majd scripts/setup-test-server.sh. Ez újraépít, migrál, regisztrálja az annotációs sémát és pótolja a bélyegképeket. Utána docker compose up -d --build a ct-annotator/ mappában.
  3. Új migrációk sorrendben: d7e9f1a3b5c7 (naplózott ideiglenes jelszavak kitakarása), e8f0a2b4c6d8 (de-id profil hash-só), f9a1b3c5d7e9 (review_of_id), a0b2c4d6e8f0 (értesítési állapot túléli a kártyát), b1c3d5e7f9a1 (sorba kerülési idő túléli a kártyát). Ellenőrzés: scripts/migrate.sh current → b1c3d5e7f9a1.
  4. Az annotációs séma 4-es verziója (segmentation_volume). A setup-szkript ezt a lépést || true-val futtatja, ezért nézd meg a kimenetét, vagy futtasd kézzel: python3 ct-annotator/scripts/register_annotation_type.py --username … --password ….
  5. Opcionális: OBJECT_LINK_SECRET a .env-ben (e nélkül a MINIO_ROOT_PASSWORD-ből származik).
  6. Több példánynál a NEW_CASES_POLLER_ENABLED=1 csak egy admin-service példányon legyen (a compose most fixen 1-et ad).
  7. A meglévő de-identifikációs profilok új hash-sót kapnak, így az új importok hash-elt értékei eltérnek a korábbiaktól. Ez szándékos, de egy tanulmányon belül vegyes lehet.
  8. Az S4 javítások nem hoznak új migrációt. A közös könyvtárak SQLAlchemy 2.1-et kérnek: a képek újraépítése (a setup-szkript megteszi) elég.
  9. Figyeléshez: curl http://<host>:<port>/health/ready szolgáltatásonként (8001, 8002, 8003, 8004, 8010) megnevezi, mi nem érhető el. A /health továbbra is csak azt mondja, hogy a folyamat fut.
  10. Visszaállítás előtt: scripts/restore-db.sh <fájl> --check-only csak ellenőrzi a mentést.
  11. A frissítés pillanatában futó feltöltések és gyorsimportok állapotát (tulajdonosjelölő nélkül) csak globális admin láthatja. A tanulmányhoz nem tartozó fiókok már nem látják az annotációtípusokat és a Store-t.
  12. Régi JPEG Lossless importok bélyegképei: docker compose exec ingestion-service python -m app.thumbnail_backfill (a setup-szkript is futtatja).
